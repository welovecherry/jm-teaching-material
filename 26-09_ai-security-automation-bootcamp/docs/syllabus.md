## 강의1 — 오리엔테이션·개발환경·변수와 자료형 (120분)
- **00–15분 과정 로드맵 안내**: 64시간(8일) 일정표. Day1~5(파이썬·API) / Day6~8(LLM·Agent) 두 축.
  모든 코드는 `agent_core/`에 누적 → 이후 과목 산출물과 합쳐져 P3 캡스톤 보안 Agent 엔진이 됨.
  - [확인질문] 우리가 오늘부터 만드는 코드가 왜 폴더(레포) 단위로 쌓여야 할까요?
- **15–35분 개발환경 설치(Python, VS Code)**: python.org에서 3.11+, "Add to PATH" 필수 체크.
  VS Code + Python 확장, `python --version`/`pip --version`로 검증. PATH 미설정 오류 해결 시연.
  - [확인질문] `python --version`이 "명령을 찾을 수 없다"고 나오면 무엇을 먼저 확인해야 할까요?
- **35–55분 가상환경(venv)·프로젝트 구조**: `python -m venv venv`, activate. `security-agent-toolkit/`
  아래 `agent_core/`, `docs/`, `config/` 등 폴더 역할 확인
  (1과목=agent_core, 2과목=network_zt, 3과목=access_control, 4과목=anomaly_detection, 5과목=soar_response).
  - [확인질문] 가상환경을 activate하지 않고 `pip install`을 하면 어떤 문제가 생길까요?
- **55–80분 변수와 기본 자료형**: 타입 선언 없음, int/float/str/bool + `type()`, **f-string 중점**
  (이후 로그 메시지·리포트 생성에 계속 사용).
  - [확인질문] `is_alert`가 bool인데 그대로 `if` 조건문에 쓸 수 있을까요?
- **80–105분 리스트·딕셔너리 기초**: list vs dict, 대표 메서드(append/keys/values/items).
  보안 로그 한 줄을 dict로 표현.
  - [확인질문] `log_event['event']` 대신 `log_event.get('event')`를 쓰면 언제 더 안전할까요?
- **105–120분 연산자·형변환**: 산술/비교/논리 연산자, `str()/int()/float()` 형변환이
  실무에서 오류 나는 이유(CSV에서 읽은 숫자가 문자열).
  - [확인질문] `int('7건')`처럼 숫자·문자가 섞이면 어떤 에러가 날까요?

## 강의2 — 조건문·반복문과 제어흐름 (120분)
- **00–25분 조건문(if/elif/else)**: 단일·다중(elif)·복합(and/or), 보안 이벤트 판정 예제.
  들여쓰기가 문법 핵심임 강조.
  - [확인질문] `failed_count`가 정확히 5일 때 어느 분기로 들어갈까요?
- **25–55분 반복문 for/while**: 리스트·딕셔너리 순회, `enumerate()`, 조건 필터링 예제.
  - [확인질문] for문 대신 while문으로 같은 필터링을 하려면 무엇이 더 필요할까요?
- **55–80분 리스트 컴프리헨션 + break/continue**.
  - [확인질문] `failed_users`에 kim01이 두 번 나오는 게 왜 문제가 될까요? (힌트: 집계)
- **80–105분 set 중복 제거 + Counter 카운팅**: `collections.Counter`로 등장 횟수 집계
  (실습 과제에서 사용자별 실패 횟수 집계에 바로 사용).
  - [확인질문] Counter 없이 직접 dict로 카운팅하면 코드가 몇 줄 더 필요할까요?
- **105–120분 정리 및 실습 과제 안내**.

## 실습 — 제어문 기반 로그 필터링 스크립트 작성 (120분)
**목표**: 오늘 배운 변수·자료형·조건문·반복문만으로 실전형 로그 필터링 스크립트를 완성.

진행 단계:
1. `agent_core/day01_basic.py` 파일 생성
2. 예제 `logs` 리스트를 20개로 확장한 샘플 데이터 작성
3. `event == 'login_failed'`만 추출해 사용자별 실패 횟수를 `Counter`로 집계
4. 2회 이상인 사용자를 '확인 필요' 목록으로 출력
5. 임계값(`THRESHOLD`)은 하드코딩하지 않고 파일 상단 변수로 분리 (config 분리 습관의 첫걸음)
6. 완성 스크립트를 조원과 교차 실행, 입력값을 바꿔가며 오류 확인

- **산출물**: `agent_core/day01_basic.py` (로그 필터링·카운팅 스크립트)
- **평가 기준**: ① 조건문·반복문으로 정상 동작 ② THRESHOLD 변수 분리 ③ 출력이 f-string으로 가독성 있게
