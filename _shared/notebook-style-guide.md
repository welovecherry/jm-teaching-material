# 주피터 교안 스타일 가이드 (전 강의 공통)

> 노트북(.ipynb) 교안을 만들 때 **항상 이 규칙을 따른다.** 강사(정민홍)와 합의된 스타일이며,
> 새 강의·새 세션에서도 동일하게 적용한다. (근거 샘플: `26-09-.../03-samples/day01-2교시-파이썬기초-v3.ipynb`)

## 1. 큰 원칙
- **최대한 쉬운 말투 · 자세하게 · 가독성 우선.** 긴 설명은 짧은 문단·불릿·콜아웃으로 쪼갠다.
- 한 셀에 개념 하나. 구조: **A(강의 흐름) + C(워크북)** 혼합.
- **커리큘럼(상세교안) 흐름을 따른다.** 어떤 개념을 언제 넣을지는 강사에게 묻기보다
  `02-source`의 상세교안 순서로 판단한다. (샘플은 양만 조절, 1시간 기준.)

## 2. 말투
- 문장은 **`~습니다`** 체. `~어요/~죠` 지양. 명사형(`~하기`, `~함`)을 적절히 섞어 간결하게.

## 3. 이모지 — 딱 5종만 반복 (셀 종류 표시용)
| 표시 | 뜻 |
|------|-----|
| 📖 | 개념(읽기) |
| 💻 | 예제(모든 케이스를 보여주는, 그대로 실행하는 칸) |
| ✍️ | 문제/직접(예제를 조금 변형해 스스로 푸는 칸) |
| ✅ | 결과(성공 예상 출력)·정답 |
| ❓ | 면접 질문 |

- 위 5개 외 장식용 이모지 금지. **구조 헤더(표지·목차·학습목표·요약·예고)는 이모지 없이 숫자**(`## 1.`).
- 주의·경고는 이모지 대신 `> **주의:**` 볼드 콜아웃으로.

## 4. 셀 리듬 (핵심) — 개념 → 예제 → 문제 반복
소절마다 다음을 반복한다 (worked example → faded practice):
1. **📖 개념** — 쉽게 설명 + "왜 이렇게 쓰지?"를 `> **왜 …?**` 볼드 콜아웃으로 미리 해소
2. **💻 예제** — 해당 개념의 **모든 케이스를 다 보여줌**. 실행 가능. 바로 뒤 **✅ 성공 출력**.
3. **✍️ 문제** — 코딩테스트처럼 **명확한 지시 + 기대 출력**. **한 문제 = 한 셀**. 정답 코드는 주지 않음.
   - 💻 예제는 **최소 3개 케이스**를 보여준다(1줄 예제 금지). 개념의 **가장 쉬운 예시부터 전부** 노출.
   - 문제 형식을 난이도에 따라 섞는다: **형식 5(버그 수정) / 2(빈칸 채우기) / 4(출력 예측) / 1(백지 코딩테스트)**.
     **형식 1(가장 어려움)은 그 소절의 마지막 문제로** 배치. 각 자료형·개념마다 문제를 만든다.

## 5. 코드 규칙
- **코드·문자열 값은 모두 영어.** 단 한국인이 이해하기 쉬운 로마자 사용(회사명 예: `hanbit`).
  사용자 예: `kim01`, `lee02`. 변수명은 **보안 맥락**으로(`failed_login_count`, `is_alert`).
- **주석만 한국어.** 각 줄에 "왜/무엇" 주석을 빠짐없이.
- 셀은 **하나씩 실행**하게 잘게(몰아치기 금지). 매 예제 뒤 **✅ 예상 출력** + 생성 후 **실제 실행 검증**.
- **자료형은 빠짐없이**: int·float·str·**bool**·**None** 모두 등장(다양한 케이스가 이후 강의 확장에 중요).
- **변수명 짓는 법**을 가르친다: 규칙(어기면 에러) vs 관습, `snake_case`(파이썬 표준),
  camelCase/PascalCase 비교, `is_`/`has_`/`can_`=불리언, 복수형=리스트, 상수=대문자.
- 실무 활용 팁을 곳곳에 쉽고 다양하게.

## 6. ❓ 면접 질문 (섹션당 1개)
- 그 주제의 **가장 핵심적인 면접 단골 질문**. 지엽적 금지.
- **반드시 '오늘 배운 범위 안'에서 답할 수 있어야** 한다. 범위를 넘으면 그 사실을 명시해 좌절 방지.
- **답의 근거를 개념 설명 본문에 자연스럽게 미리 심어 둔다.**
- **모범답안(접기)은 넣지 않는다.** 학생이 교안 본문을 되짚어 스스로 답을 찾게 한다.
  (질문 + "본문에서 답을 찾아보세요" 안내까지만.) 프롬프트 예시도 안 넣음(학생이 알아서 AI 활용).

## 7. 마무리
- **오늘 요약**(번호 목록) → **종합 퀴즈(객관식, 정답 접기)** → **다음 시간 예고**.

## 8. 파일명·버전·날짜
- 파일명: `dayNN-N교시-주제-vN.ipynb` (하이픈 통일).
- **샘플(`03-samples`)**: 표지 셀에 `만든 날짜 · 버전` 표기 유지.
- **최종본(`04-build`)**: 표지에서 **만든 날짜·버전 삭제**.
- 버전: 승인 전에는 같은 vN 개선(덮어씀), 승인된 vN 개정 시 v(N+1). 강사가 새 버전 요청 시 그에 따름.

## 9. 생성 방식
- 노트북은 **파이썬 생성 스크립트**(`md()/code()` 헬퍼)로 찍어낸다 → 리듬이 일정하게 유지.
  스크립트는 같은 폴더에 `dayNN-N교시-build.py`로 보관(재생성 가능).

## 10. 시간 충실 & 2레이어 (상세교안 정렬) ★
- **시간 우선**: 모든 섹션 헤더에 **상세교안의 분(分) 범위**를 표기한다
  (예: `## 1. 변수와 자료형 · 상세교안 55–80분`). **본 수업 분량을 그 시간에 맞춘다.**
- **커리큘럼(상세교안)이 빈약하므로 보충 내용을 적극 추가한다.** 기초 배경지식(예: "str이 뭔지"부터),
  쉬운 예제, 변수명 짓는 법 등을 **충분히** 넣는다. 단, 다른 날이 '핵심 주제'로 깊게 다루는 건
  존중해 맛보기까지만(예: PEP8 네이밍 심화는 Day2). "그 자리에 넣지 마라"는 옛 규칙은 폐기.
- **학생용 본문에 '상세교안'이라는 말을 쓰지 않는다.** 시간은 `· 55–80분`처럼만 표기.
- **개념은 벽글 금지 — 숫자/불릿을 적극 사용.** 처음 배우는 학생 기준으로 0에서부터 설명.
- **예제는 가장 쉬운 한 줄부터 잘게 단계적으로** 올린다(어려운 예제를 갑자기 주지 않기).
- **2레이어 구성**:
  - **본 수업** = 상세교안 그대로. 📖개념 + 💻예제(상세교안 예제 기반) + 가벼운 ✍️문제 1개 + 상세교안의 `[확인질문]`.
  - **[심화·자습]** = 우리가 만든 풍부한 예제·다양한 문제 형식·❓면접질문·범위 밖 개념(None 등).
    각 섹션 끝에 `## [심화·자습] …` 헤더로 분리. "시간 남으면·자습·리추얼에서" 안내.
  - 커리큘럼이 빈약할 때는 심화 레이어를 넉넉히 채워도 좋다. 못 다룬 분량은 리추얼 시간에 소화.
- **주의(주피터 한계)**: `<details>` 접기는 **마크다운 셀 안**에서만 동작하며 **코드 셀은 못 감춘다.**
  그래서 심화 코드는 접지 말고 `## [심화·자습]` 헤더로 **라벨링**만 한다. (면접질문 등 마크다운은 `<details>` 가능)

## 11. 실습(Lab)은 강사가 만든다
- **실습의 구체 내용(베이스라인 코드·상세 실습 문제·정답 코드)은 강사(정민홍)가 직접 작성**한다.
- Claude는 실습을 지어내지 않는다. 상세교안 실습 섹션(목표·진행단계·산출물·평가기준)을
  **학생용 안내서 구조**로만 옮기고(체크박스·시간배분·힌트 자리), 코드는 강사 몫으로 비워 둔다.
