classifier_registry = {

return tags if tags else \['미분류'\]

강의2 - 로그인·트래픽 탐지 룰 구현

*총 120분*

**00-25분 비정상 로그인 탐지 룰 설계**

일정 시간(예: 10분) 내 동일 계정의 로그인 실패가 임계값(예: 5회)을 넘으면 탐지하는 룰과, 업무시간 외 로그인을 탐지하는 룰(3과목 조건부 접근과 연결)을 설계한다.

규칙: 최근 10분 내 동일 user의 login_failed 이벤트가 5건 이상 -\> 탐지

*\[확인질문\] 임계값을 3회로 낮추면 탐지는 더 민감해지지만 어떤 부작용(오탐 증가)이 생길 수 있을까요?*

**25-50분 로그인 탐지 룰 코드 구현**

실패횟수 기반 탐지(detect_bruteforce)와 업무시간외 탐지(detect_offhour_login) 함수를 라이브 코딩한다.

def detect_bruteforce(logs, user, window_min=10, threshold=5):

recent = \[l for l in logs if l\['user'\]==user and l\['event_type'\]=='login_failed'\]

return len(recent) \>= threshold

*\[확인질문\] 이 함수가 '최근 10분'이라는 시간 조건을 아직 반영하지 않았는데, 어떻게 보완해야 할까요?*

**50-75분 트래픽 급증이 의미하는 것과 이동평균**

평소 대비 방화벽 로그·요청량이 급격히 증가하는 트래픽 급증의 의미와, 일시적 튐과 지속적 증가 추세를 구분하는 이동평균(Moving Average) 개념을 설명한다.

최근 5분 평균 요청수: 100건

이번 1분 요청수: 800건 -\> 평균 대비 8배 급증 -\> 탐지

*\[확인질문\] 트래픽 급증이 반드시 공격이라고 단정할 수 있을까요? 정상적인 트래픽 증가와 어떻게 구분해야 할까요?*

**75-100분 트래픽 급증 탐지 코드 구현**

pandas의 rolling() 함수로 이동평균을 계산하고, 현재 값과 비교해 급증을 탐지하는 detect_traffic_spike() 함수를 라이브 코딩한다.

def detect_traffic_spike(counts_series, window=5, multiplier=3):

moving_avg = counts_series.rolling(window).mean()

spikes = counts_series\[counts_series \> moving_avg \* multiplier\]

return spikes

*\[확인질문\] rolling(window=5)에서 window 값을 크게 하면(예: 60) 이동평균은 더 안정적이 될까요, 더 민감해질까요?*

**100-120분 실습 안내**

def check_chain(user_events, pattern, window_minutes=30):

for i, e in enumerate(user_events):

if e\['event_type'\] == pattern\[0\]:

window_end = e\['timestamp'\] + timedelta(minutes=window_minutes)

following = \[x for x in user_events\[i+1:\] if x\['timestamp'\] \<= window_end\]

if any(x\['event_type'\]==pattern\[1\] for x in following):

return True

return False

*총 120분*

**00-20분 오탐(False Positive)과 미탐(False Negative)**

실제로는 정상인데 이상으로 잘못 탐지하는 오탐과, 실제로는 이상인데 놓치는 미탐을 표(실제 정상/이상 x 탐지 정상/이상)로 설명한다.

실제 정상 실제 이상

탐지 이상(경보) False Positive(오탐) True Positive

*\[확인질문\] 보안관제 담당자 입장에서 오탐이 너무 많으면 어떤 문제(alert fatigue)가 생길까요? 미탐이 많으면 어떤 문제가 생길까요?*

**20-50분 정밀도(Precision)와 재현율(Recall)**

경보 중 실제 위협 비율인 정밀도, 실제 위협 중 놓치지 않고 잡아낸 비율인 재현율의 개념과 계산식을 설명하고, 둘 사이의 트레이드오프를 짚는다.

정밀도 = TP / (TP + FP)

재현율 = TP / (TP + FN)

*\[확인질문\] 임계값을 낮춰서 탐지를 더 민감하게 만들면 재현율은 어떻게 변할까요? 정밀도는요?*

**50-80분 보안관제에서 어느 지표를 우선할 것인가**

일반적으로 초기 탐지 단계에서는 재현율(놓치지 않는 것)을 우선하고, 이후 사람이 검토하는 단계에서 정밀도를 높이는 실무 전략을 설명한다(5과목 SOAR의 승인 게이트와 연결).

*\[확인질문\] 재현율을 우선한다는 것은, 오탐이 좀 늘더라도 무엇을 지키겠다는 뜻일까요?*

**80-105분 튜닝 프로세스 개관**

*\[확인질문\] 튜닝을 한 번만 하고 끝내지 않고 반복해야 하는 이유는 무엇일까요?*

*총 120분*

**00-25분 라벨링된 테스트셋으로 성능 측정**

정답(실제 정상/이상 여부)이 미리 라벨링된 테스트 데이터셋을 활용해, 지금까지 만든 탐지 로직의 정밀도·재현율을 계산하는 함수를 구현한다.

def evaluate_detector(events_with_labels, detector_func):

tp=fp=fn=tn=0

for e in events_with_labels:

predicted = detector_func(e); actual = e\['is_actual_anomaly'\]

if predicted and actual: tp+=1

elif predicted and not actual: fp+=1

elif not predicted and actual: fn+=1

else: tn+=1

precision = tp/(tp+fp) if (tp+fp) else 0

recall = tp/(tp+fn) if (tp+fn) else 0

return {'precision': precision, 'recall': recall}

강의1 - AI 기반 우선순위 분류와 파이프라인 통합 설계

*총 120분*

**00-20분 1~4일차 종합 지도**

정규화(1일차) → 유형분류·개별탐지룰(2일차) → 고급탐지·상관분석(3일차) → 튜닝(4일차)까지의 파이프라인을 한 장으로 정리하며 오늘이 최종 통합의 날임을 강조한다.

*\[확인질문\] 이 4일 중 1과목(AI·자동화 기초)의 어떤 스킬이 가장 많이 재사용되었나요?*

**20-50분 1과목 LLM 요약 기능과의 연결**

탐지·점수화된 이벤트 목록을 1과목 event_summarizer.py에 입력해, 사람이 읽기 좋은 자연어 요약을 자동 생성하는 통합 방식을 설계한다.

고위험 이벤트 목록(anomaly_detection) -\> event_summarizer.py(agent_core) -\> 자연어 요약 + 우선순위

*\[확인질문\] 이상탐지 모듈이 직접 LLM 요약 코드를 새로 짜지 않고 1과목 모듈을 재사용하는 것이 왜 효율적일까요?*

**50-80분 우선순위 분류 기준 최종 설계**

위험점수(3일차) + 상관분석 매칭 여부 + 자산 중요도(DB서버가 일반PC보다 중요)를 종합해 high/medium/low 우선순위를 매기는 최종 기준표를 완성한다.

우선순위 = f(위험점수, 상관분석 매칭여부, 자산중요도)

예: 위험점수 70점 이상 OR 상관분석 매칭 시 -\> high

*\[확인질문\] 자산 중요도를 우선순위 계산에 포함시켜야 하는 이유는 무엇일까요?*

**80-105분 agent_core 연동 지점 확인**

anomaly_detection의 핵심 함수(calculate_risk_score, classify_event 등)가 1과목 tool_router.py에 어떻게 등록되어 AI Agent가 호출할 수 있는 도구가 되는지 코드로 확인한다.

tool_registry\['classify_and_score'\] = anomaly_detection.classify_and_score

tool_registry\['summarize_high_risk_events'\] = anomaly_detection.summarize_pipeline

*\[확인질문\] 이렇게 등록해두면 최종 캡스톤에서 'AI 보안 이벤트 분류·초동대응봇'이 이 기능을 어떻게 활용하게 될까요?*

**105-120분 정리**

우선순위 분류 기준과 연동 설계를 정리하고 통합 구현으로 넘어간다.

강의2 - 전체 파이프라인 통합 구현과 발표 준비

*총 120분*

**00-25분 pipeline.py 오케스트레이션 작성**

normalize, classify, login_detection, traffic_detection, advanced_detection, correlation, evaluation 모듈을 모두 import해 run_anomaly_pipeline() 함수의 골격을 라이브 코딩한다.

def run_anomaly_pipeline(config_path):

config = load_config(config_path)

events = normalize_all(config\['log_paths'\])

scored = \[calculate_risk_score(e, detectors, weights) for e in events\]

prioritized = assign_priority(scored)

return prioritized

*\[확인질문\] 각 단계를 독립 함수로 유지하며 오케스트레이션 함수에서 순서대로 호출하는 방식, 왜 하나의 거대한 함수보다 나을까요?*

**25-55분 high 우선순위 이벤트 자연어 요약 연동**

high로 분류된 이벤트를 1과목 방식(요약 프롬프트+청크 처리)으로 자연어 요약하고 리포트로 저장하는 코드를 완성한다.

*\[확인질문\] 모든 이벤트가 아니라 high 우선순위 이벤트만 요약하는 이유는 무엇일까요? (비용, 담당자 집중도)*

**55-80분 코드 리뷰 체크리스트**

config 하드코딩 여부, 예외처리 누락 여부, 로깅 일관성, 함수 재사용성 체크리스트로 anomaly_detection/ 전체를 리뷰한다.

*\[확인질문\] 체크리스트 중 스스로 가장 취약하다고 생각하는 항목은 무엇인가요?*

**80-105분 디버깅 실습 - 의도적 오류 주입**

강사가 준비한 '고장난 pipeline.py' 샘플을 학습자들이 직접 디버깅해보는 실습으로 예외처리·로깅의 중요성을 체감하게 한다.

*\[확인질문\] 에러 메시지(traceback)를 읽을 때 가장 먼저 확인해야 할 정보는 무엇일까요?*

**105-120분 발표 준비 안내**

실습에서 진행할 전체 파이프라인 시연과 발표를 안내한다.

실습 - AI 기반 이벤트 요약·우선순위 분류 자동화 구현 및 발표

*총 120분*

**실습 목표:** 1~4일차 모든 탐지 모듈을 통합하고 AI 요약·우선순위 분류까지 이어지는 최종 파이프라인을 완성해 시연한다.

**진행 단계**

1\. anomaly_detection/pipeline.py를 생성해 1~4일차 모든 모듈을 import한다

2\. run_anomaly_pipeline() 함수로 원본 로그 입력부터 위험점수·우선순위 산출까지 전체 흐름을 통합한다

3\. high 우선순위로 분류된 이벤트를 자연어 요약한다

4\. 결과를 anomaly_detection_report_YYYYMMDD.json/md로 저장한다

5\. agent_core/tool_router.py에 이상탐지 모듈의 핵심 함수를 등록하는 코드를 작성해 연동을 확인한다

6\. 5분 내외 발표 자료를 준비해 팀별로 전체 파이프라인을 시연하고, 피드백을 anomaly_detection/day05_retrospective.md에 정리한다

**산출물:** anomaly_detection/pipeline.py, anomaly_detection_report\_\*.json, day05_retrospective.md

**평가 기준**

\- 1~4일차 모든 모듈이 하나의 파이프라인으로 오류 없이 통합되는가

\- high 우선순위 이벤트에 대한 자연어 요약이 정상 생성되는가

\- agent_core 연동 지점을 발표에서 명확히 설명하는가
