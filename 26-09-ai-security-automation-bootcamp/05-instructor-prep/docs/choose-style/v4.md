# 【v4】 2과목 Day1 · OSI 7계층 (강의1 앞 1시간) — 스토리텔링형 + 시간표 + 개념풀이 + 분량 확대

!!! note "스타일 확정본 방향 (v1 스토리텔링형 기반 개선)"
    v1(스토리텔링)을 기반으로 ① 상단 **오늘의 시간표**(v2에서), ② **어려운 개념 쉽게 풀기** 섹션 신설, ③ 각 블록 **분량을 강의 시간에 맞게 대폭 확대**했습니다.

> **오늘 한 문장:** 네트워크 통신을 7개 층으로 나눈 "지도"를 손에 넣어, 문제가 생겼을 때 어디를 봐야 할지 짚을 수 있게 됩니다.
> **왜 배우나:** 이 지도가 있어야 "왜 접속이 안 되죠?"에 **원인을 좁혀** 답할 수 있고, 뒤에 배울 접근통제·이상탐지·SOAR 과목의 **밑바탕**이 됩니다.

## 오늘의 시간표 (강의1 앞 1시간)
| 시간 | 주제 | 핵심 한 줄 |
|------|------|-----------|
| 00-20분 | 네트워크를 배우는 이유 | 지도가 있어야 장애 원인을 좁힌다 |
| 20-50분 | OSI 1·2·3계층 | 데이터를 목적지 기기까지 **나른다** |
| 50-80분 | OSI 4·5·6·7계층 | 기기 **안**에서 올바른 프로그램에 전달한다 |

## 이 시간에 나오는 어려운 개념 쉽게 풀기
> 본격 설명 전에, 오늘 튀어나올 어려운 말들을 미리 아주 쉽게 풀어둡니다. (본문에서 또 나옵니다)

| 용어 (한글발음) | 한 줄 뜻 (아주 쉽게) | 비유 |
|----------------|----------------------|------|
| **프로토콜(protocol, 프로토콜)** | 통신할 때 서로 지키기로 한 "약속·규칙" | 편지 봉투에 주소 쓰는 규칙 |
| **OSI 7계층(오에스아이)** | 통신 과정을 7층 건물처럼 나눈 지도 | 7층짜리 물류센터 |
| **패킷(packet, 패킷)** | 데이터를 잘게 나눠 담은 한 덩어리 | 택배 상자 하나 |
| **MAC 주소(맥)** | 기기마다 평생 붙어 있는 고유 번호 | 주민등록번호 |
| **IP 주소(아이피)** | 지금 접속한 위치를 가리키는 주소 | 지금 사는 집 주소 |
| **스위치(switch)** | 같은 동네(네트워크) 안에서 배달하는 장비 | 우리 아파트 경비실 |
| **라우터(router, 라우터)** | 다른 동네로 넘겨주는 장비 | 지역 간 택배 허브 |
| **ARP(아르프)** | IP 주소로 상대의 MAC 주소를 알아내는 절차 | "그 집 사람 이름표가 뭐죠?" 묻기 |
| **포트(port, 포트)** | 한 컴퓨터 안에서 어느 프로그램인지 구분하는 번호 | 건물 안 "몇 호실" |
| **TCP / UDP(티씨피 / 유디피)** | 데이터 보내는 두 방식(확실히 / 빠르게) | 등기우편 / 일반우편 |

## ⏱️ 00-20분 · 우리가 네트워크를 배우는 진짜 이유  *(약 20분)*

> 🎤 *"여러분, 고객사에서 전화가 옵니다. '왜 갑자기 접속이 안 되나요?' 딱 이 한 마디예요. 자, 어디부터 확인하실 건가요? 케이블? IP? 방화벽? 서버? …사실 이 순간, 머릿속에 '지도'가 없으면 우리는 아무 데나 막 찔러보게 됩니다. 오늘 그 지도를 그려보겠습니다."*

**🧠 쉽게 이해하기**

보안관제(SOC, "쏙", Security Operations Center — 보안 상황을 24시간 지켜보는 팀)에서 가장 흔한 상황이 이겁니다. 고객은 **증상만** 말하고("안 돼요", "느려요"), 원인은 우리가 찾아야 합니다.

이때 통신 과정을 **여러 단계로 쪼개 볼 줄 알면**, "여기까지는 정상, 여기서 막혔다"라고 범위를 좁힐 수 있습니다. 이게 오늘 배울 OSI 7계층이 주는 힘입니다.

한 가지 더. 이 2과목(네트워크·제로트러스트)은 그 자체로도 중요하지만, **뒤에 배울 3·4·5과목(접근통제·이상탐지·자동대응)이 전부 이 위에 얹혀** 있습니다. 지금 지도를 확실히 그려두면 남은 과목이 훨씬 쉬워집니다.

!!! example "쉬운 비유 — 계층으로 나눈다는 것"
    택배가 집까지 오는 과정을 떠올려 보세요. ①물건을 상자에 담고 → ②송장(주소)을 붙이고 → ③트럭에 싣고 → ④도로를 달려 → ⑤집 앞에 내려놓고 → ⑥초인종을 누릅니다. 하나라도 문제가 생기면 우리는 "어느 단계에서 막혔지?"를 봅니다. 네트워크도 똑같이 **단계(계층)로 나눠** 보면 문제 지점을 콕 집을 수 있습니다.

!!! tip "실무 팁"
    실무에선 이 진단을 **아래에서 위로(bottom-up)** 합니다. 물리 → IP → 포트 → 서비스 순서로 올라가며 "여기까진 OK"를 확인해 나가면, 한 번에 원인 구간이 좁혀집니다. 오늘 배우는 계층 순서가 곧 이 점검 순서입니다.

!!! question "확인질문 · 나의 답"
    **Q. 고객이 '인터넷이 느려요'라고만 말했을 때, 어느 계층부터 확인해야 원인을 좁힐 수 있을까요?**

    A. 아래(물리)에서 위(응용)로 순서대로 봅니다. 먼저 **케이블·연결(1계층)** → **IP를 받아 통신이 되는지(3계층, 핑)** → **특정 서비스 포트가 열리는지(4계층)**. 이렇게 아래부터 하나씩 지우면 "3계층까진 정상, 그 위가 문제"처럼 **범위가 좁혀집니다.** 무작정 서버부터 의심하는 것보다 훨씬 빠릅니다.

## ⏱️ 20-50분 · 지도의 아래 세 칸 — 1·2·3계층  *(약 30분, 오늘의 핵심)*

이 30분이 오늘의 심장입니다. OSI(오에스아이) 7계층 중 **아래 세 칸**을 봅니다. 이 세 칸의 공통 임무는 딱 하나 — **"데이터를 목적지 기기까지 실제로 날라다 주는 것"**입니다. 위층은 나중에(50분~) 봅니다.

시작 전에 하나만 심어두겠습니다. 데이터는 그냥 통째로 날아가지 않고, **잘게 쪼갠 덩어리(패킷)**에 **층마다 봉투를 하나씩 덧씌워** 내려갑니다. 이걸 **캡슐화(encapsulation, 인캡슐레이션)**라고 합니다.

!!! example "쉬운 비유 — 캡슐화(봉투 덧씌우기)"
    편지를 부친다고 해봅시다. ①편지지(데이터)를 → ②봉투에 넣어 받는 사람 이름을 쓰고 → ③그 봉투를 택배 상자에 넣어 집 주소를 붙입니다. 층을 내려갈수록 **바깥 포장이 하나씩 늘어납니다.** 받는 쪽은 반대로 포장을 하나씩 벗기며 올라갑니다. 네트워크도 똑같이 2계층·3계층에서 각자 자기 "봉투(헤더)"를 덧씌웁니다.

### 1계층 — 물리(Physical): "길과 전선"

가장 아래, 실제로 전기 신호가 흐르는 곳입니다.

- **무엇:** 랜선(UTP 케이블, "유티피"), 광케이블, 그리고 신호를 그냥 퍼뜨리기만 하는 허브(hub).
- **다루는 것:** 0과 1이라는 **전기·빛 신호**. "지능"은 없습니다. 그냥 신호를 흘려보낼 뿐입니다.
- 편지로 치면 **도로 그 자체**예요.

!!! tip "실무 팁 — 1계층 장애는 의외로 흔하다"
    "인터넷이 안 돼요"의 상당수가 사실 1계층입니다. 랜선이 반쯤 빠졌거나, 포트 불량이거나, 케이블이 눌려 끊어졌거나. 그래서 점검을 **"케이블부터"** 시작하는 겁니다. 스위치 포트의 **불빛(LED)이 켜지는지**가 1계층 생존의 첫 신호입니다.

### 2계층 — 데이터링크(Data Link): "같은 동네 안 배달"

여기서 처음으로 **주소**가 등장합니다.

- **주소:** **MAC(맥, Media Access Control) 주소.** 랜카드마다 공장에서 찍혀 나오는, 세상에 하나뿐인 기기 고유번호입니다.
- **생김새:** `00:1A:2B:3C:4D:5E`처럼 16진수 6칸. 앞 3칸은 **제조사 번호(OUI)**라, 이것만 봐도 "아, 이건 애플 기기구나"를 알 수 있습니다.
- **장비:** **스위치(switch).** 스위치는 "어느 포트에 어느 MAC이 붙어 있는지"를 **MAC 주소 테이블**로 스스로 학습해서, 같은 네트워크 안에서 정확한 기기에게만 데이터를 보냅니다.

!!! example "쉬운 비유 — MAC 주소"
    MAC 주소는 **주민등록번호**입니다. 태어날 때(공장에서 만들 때) 정해지고, 이사를 가도(다른 네트워크에 연결해도) 바뀌지 않습니다. 스위치는 우리 **아파트 경비실**이에요. "302호 김씨"에게 온 택배를 정확히 302호로만 올려보냅니다. 단, 경비실은 **우리 아파트 안**에서만 배달할 수 있습니다. 다른 단지로는 못 보냅니다.

### 3계층 — 네트워크(Network): "다른 동네로 보내기"

우리 동네(네트워크)를 벗어나 다른 네트워크로 가려면, 경비실(스위치)로는 안 됩니다. 새 주소와 새 장비가 필요합니다.

- **주소:** **IP(아이피, Internet Protocol) 주소.** `192.168.0.10`처럼 생겼고, **접속한 위치에 따라 바뀝니다.**
- **장비:** **라우터(router, 라우터).** IP를 보고 "이 데이터는 어느 네트워크로 보내야 하나"를 **라우팅 테이블**로 판단해 길을 잡아줍니다.
- **게이트웨이(gateway, 게이트웨이):** 우리 동네에서 바깥으로 나가는 **"정문"** 역할을 하는 라우터 주소입니다. 다른 네트워크로 가는 데이터는 일단 이 정문으로 모입니다.

!!! example "쉬운 비유 — IP 주소와 라우터"
    IP 주소는 **지금 사는 집 주소**입니다. 이사 가면 바뀌죠. 라우터는 **지역 간 택배 허브**예요. 서울 우리 집에서 부산으로 택배를 보내면, 동네 경비실(스위치)이 아니라 **택배 허브(라우터)**가 "부산 방향"으로 넘겨줍니다.

**🔑 그래서 MAC과 IP, 왜 둘 다 필요한가?**

| | MAC(맥) 주소 | IP(아이피) 주소 |
|---|---|---|
| 비유 | 주민등록번호(평생 고정) | 사는 집 주소(바뀜) |
| 담당 범위 | **같은 네트워크(동네) 안** | **네트워크와 네트워크 사이** |
| 계층/장비 | 2계층 / 스위치 | 3계층 / 라우터 |

둘을 이어주는 다리가 **ARP(아르프, Address Resolution Protocol)**입니다. "이 IP 주소를 가진 기기의 MAC이 뭐죠?"라고 같은 네트워크에 물어보는 절차예요. IP로 목적지 동네를 찾아가고, 마지막엔 MAC으로 정확한 기기에 꽂아 넣습니다.

### 👀 한눈에 보는 시나리오 — 데이터가 실제로 흐르는 길

**상황 A. 같은 사무실 옆자리 PC로 파일 보내기**

1. 같은 네트워크(동네)이므로 **IP로 상대를 특정**하고,
2. **ARP로 상대의 MAC 주소**를 알아낸 뒤,
3. **스위치(2계층)**가 그 MAC을 보고 옆자리 PC로 바로 전달합니다.
   → 라우터를 거칠 필요가 없습니다. (동네 안 배달)

**상황 B. 구글 서버(인터넷 너머)로 접속하기**

1. 목적지가 **다른 네트워크**이므로, 데이터를 일단 **게이트웨이(정문 라우터)**로 보냅니다.
2. **라우터(3계층)**가 IP를 보고 인터넷 방향으로 길을 잡아 넘깁니다.
3. 여러 라우터를 거쳐 구글 네트워크에 도착하면, 그 동네의 스위치가 마지막에 **MAC으로** 실제 서버에 꽂아 넣습니다.

!!! tip "실무 팁 — 직접 눈으로 확인하는 명령어"
    강의 중 시연하면 좋습니다. (윈도우 기준)
    - `ipconfig` → 내 **IP 주소**와 **게이트웨이(정문)** 주소 확인
    - `getmac` 또는 `ipconfig /all` → 내 랜카드 **MAC 주소** 확인 (`00:1A:2B:...` 형태)
    - `arp -a` → 내 PC가 알아낸 **"IP ↔ MAC 짝꿍표"** 보기
    - `tracert google.com` → 구글까지 **거쳐 가는 라우터들**을 한 줄씩 보여줌 (3계층이 여러 번 등장!)

!!! warning "학생이 헷갈리는 지점 (미리 답 준비)"
    - **"스위치랑 라우터랑 뭐가 달라요?"** → 스위치는 **같은 네트워크 안**(MAC 기반), 라우터는 **네트워크 사이**(IP 기반). 경비실 vs 택배 허브.
    - **"IP만 있으면 되지 MAC은 왜 필요해요?"** → IP는 "어느 동네"까지만 데려다줍니다. 마지막에 **정확한 기기에 꽂으려면** 그 동네에서 통하는 이름표(MAC)가 필요합니다.
    - **"MAC은 안 바뀌는데 IP는 왜 바뀌어요?"** → MAC은 기기에 붙은 것(주민번호), IP는 지금 연결된 위치(집 주소). 카페 와이파이에 연결하면 IP는 그 카페 것으로 바뀌지만 내 노트북 MAC은 그대로입니다.

!!! question "확인질문 · 나의 답"
    **Q. 같은 사무실 안 두 PC가 통신할 때와, 인터넷 너머 서버와 통신할 때 쓰는 주소 체계가 다른 이유는?**

    A. 같은 사무실(같은 네트워크) 안에서는 **MAC 주소(2계층)**로 바로 찾아갑니다 — 같은 동네라 이름표만으로 충분하죠. 하지만 인터넷 너머 다른 네트워크로 가려면 **IP 주소(3계층)**가 있어야 라우터가 "어느 네트워크로 보낼지" 길을 잡습니다. 동네 안 배달(경비실)과 타 지역 배송(택배 허브)에 필요한 정보가 다른 것과 같은 이치입니다.

## ⏱️ 50-80분 · 지도의 위 네 칸 — 4·5·6·7계층  *(약 30분)*

아래 세 칸이 "목적지 **기기까지** 배달"이었다면, 위 네 칸은 그 기기에 **도착한 다음**의 이야기입니다. "기기 안에서 올바른 프로그램에 전달하고, 사람이 쓸 수 있는 형태로 만드는" 부분이죠.

### 4계층 — 전송(Transport): "어느 창구로 갈까"

데이터가 목적지 컴퓨터에 도착해도, 그 안엔 웹브라우저·메일·화상회의 같은 여러 프로그램이 동시에 돌고 있습니다. 이걸 구분해 주는 게 **포트(port, "포트") 번호**입니다.

!!! example "쉬운 비유 — IP는 건물, 포트는 호실"
    **IP 주소가 "건물 주소"**라면, **포트는 "그 건물 안 몇 호실"**입니다. 택배가 건물(IP)에 도착한 뒤, 경비원이 "이건 302호(웹), 저건 505호(메일)"로 나눠 올려보내는 것과 같습니다.

여기서 데이터를 보내는 **두 가지 방식**도 나뉩니다.

| | TCP(티씨피) | UDP(유디피) |
|---|---|---|
| 비유 | 등기우편(받았는지 확인) | 일반우편(확인 없이 빠르게) |
| 특징 | 신뢰성 높음, 조금 느림 | 빠름, 유실 가능 |
| 언제 | 웹·파일 전송(정확해야) | 실시간 영상·DNS 질의(빨라야) |

!!! tip "실무 팁"
    화상회의가 가끔 화면이 깨져도 계속 진행되는 이유가 UDP입니다. "한 장 빠져도 다음 장으로 빨리 가는 게" 더 중요하거든요. 반대로 파일 다운로드는 한 조각만 빠져도 파일이 깨지니 TCP로 **빠짐없이** 받습니다.

### 5·6계층 — 세션·표현(Session·Presentation): "연결 관리와 통역"

- **세션(5):** 연결을 언제 열고 유지하고 닫을지 관리합니다.
- **표현(6):** 데이터를 서로 알아볼 수 있게 **암호화·인코딩**합니다. (HTTPS의 자물쇠가 여기와 관련)
- 실무에서 이 두 층을 따로 깊게 팔 일은 상대적으로 적어, 오늘은 **"이런 역할이 있다"**까지만 잡습니다.

### 7계층 — 응용(Application): "사람이 마주하는 화면"

우리가 실제로 쓰는 서비스 층입니다. 웹(HTTP), 메일(SMTP), 이름풀이(DNS) 같은 것들이 여기 삽니다. 자주 보는 포트는 통째로 외워두면 두고두고 편합니다.

| 포트 | 서비스 | 한 줄 뜻 |
|------|--------|----------|
| `80` | HTTP | 일반 웹 |
| `443` | HTTPS | 암호화된 웹(자물쇠) |
| `22` | SSH | 서버 원격 접속 |
| `53` | DNS | 도메인 이름 → IP 변환 |

!!! tip "실무 팁 — 포트를 알면 로그가 읽힌다"
    방화벽 로그에 `dst port 22`(SSH)가 갑자기 잔뜩 찍히면 "누가 서버에 원격 접속을 계속 시도하는구나"라고 바로 감이 옵니다. 이건 뒤 4과목(이상탐지)에서 **무차별 로그인 시도 탐지**로 다시 만납니다. 포트 지식은 그때 그대로 쓰입니다.

!!! warning "학생이 헷갈리는 지점 (미리 답 준비)"
    - **"포트 번호를 내가 정하나요?"** → 웹=80/443, SSH=22처럼 **널리 약속된 번호**가 있습니다(well-known port). 우리가 매번 정하는 게 아니라 관습·표준입니다.
    - **"IP랑 포트는 항상 같이 다녀요?"** → 네, 보통 `192.168.0.10:443`처럼 **주소:호실** 짝으로 다닙니다. 건물만 알고 호실을 모르면 배달이 안 되니까요.

!!! question "확인질문 · 나의 답"
    **Q. 같은 서버(같은 IP)에서 웹사이트와 이메일 서비스를 동시에 운영할 수 있는 이유는?**

    A. **포트 번호(4계층)** 덕분입니다. IP는 같아도 웹은 `443`번 호실로, 메일은 다른 포트로 들어오기 때문에, 서버는 "이건 웹, 저건 메일"이라고 구분해 각 프로그램에 나눠줄 수 있습니다. 건물 주소(IP)는 하나여도 호실 번호(포트)로 사무실을 구분하는 것과 같습니다.

- [ ] 캡슐화(봉투 덧씌우기)를 한 문장으로 설명할 수 있다
- [ ] MAC(2계층) vs IP(3계층)를 비유로 구분하고, **왜 둘 다 필요한지** 답한다
- [ ] 스위치 vs 라우터, ARP를 설명할 수 있다
- [ ] `ipconfig` / `getmac` / `arp -a` / `tracert`를 직접 쳐서 시연할 수 있다
- [ ] 포트 번호가 왜 필요한지(같은 IP, 여러 서비스) 설명한다
- [ ] TCP vs UDP를 비유로 든다
- [ ] 자주 쓰는 포트 4개(80/443/22/53)를 외웠다
- [ ] 확인질문 3개 + 학생 예상질문에 답할 수 있다
