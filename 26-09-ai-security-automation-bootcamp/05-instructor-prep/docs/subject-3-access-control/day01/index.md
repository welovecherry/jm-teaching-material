## 이 하루에 나오는 어려운 용어

| 용어 (한글발음) | 한 줄 뜻 (아주 쉽게) | 비유 |
|----------------|----------------------|------|
| **접근통제(Access Control, 액세스 컨트롤)** | 누가 무엇에 접근할지 정하고 지키기 | 건물 출입 통제 |
| **인증 / 인가** | 누구인지 확인 / 무엇을 해도 되는지 확인 | 신분증 / 출입등급 |
| **RBAC(알백)** | 역할을 중간에 두고 권한 관리 | 직책에 권한 묶기 |
| **계정·권한·역할·그룹** | 누구·무엇을·권한묶음·사람묶음 | 사원·열쇠·직책·부서 |
| **최소권한(least privilege)** | 꼭 필요한 만큼만 허용 | 필요한 열쇠만 |
| **권한 매트릭스** | 부서×시스템 접근 수준 표 | 좌석 배치도 |
| **예외 관리** | 기준 밖 요청을 승인·기록·회수 | 임시 출입증 |
| **`dict` / `list`** | 이름표 상자 / 순서 목록 | 전화번호부 / 장보기 목록 |
| **`.get(키, 기본값)`** | 없으면 에러 대신 기본값 | 없으면 빈손 |
| **JSON(제이슨)** | 사람이 읽는 데이터 파일 형식 | 항목별 카드 |
| **CLI(씨엘아이)** | 명령 한 줄로 쓰는 도구 | 리모컨 |
| **PDP(피디피)** | 접근 허용을 판단하는 두뇌 | 심사관 |

## 오늘의 최종 목표 (Day 1을 마치면)
- [ ] 계정→역할→권한(RBAC) 구조를 비유와 코드로 설명한다
- [ ] `has_permission()`·`assign_role()`을 한 줄씩 설명하고 직접 실행한다
- [ ] 데이터를 JSON으로 분리하는 이유를 안다
- [ ] 부서×시스템 권한 매트릭스를 설계하고, 예외에 만료일이 필요한 이유를 안다
- [ ] `check_policy()`·`evaluate_access()`로 정책+예외 통합 판단을 구현한다
