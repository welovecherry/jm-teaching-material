# 3과목 Day 3 · 개요 — 접근 점검·회수 프로세스 & 과다권한 탐지

!!! note "이 Day 사용법"
    Day 2가 "권한을 주는 절차"였다면, Day 3은 **"이미 준 권한이 아직도 적절한가"를 되돌아보는(review)** 날입니다. 오늘의 키워드는 **과다권한(Over-privilege)** 과 **정기 점검(access review)** 입니다.

> **오늘 한 문장:** 시간이 지나면 권한은 자연스럽게 '너무 많아집니다'. 90일 미사용·부서 불일치·예외 만료 같은 신호로 **과다권한 후보를 자동 탐지**하고, 그것을 **정기 점검 리포트**로 만듭니다.
> **왜 배우나:** 실무 사고의 큰 축이 "퇴사·부서이동했는데 권한이 안 지워진" 방치 계정입니다. 오늘 만드는 탐지 함수가 그런 유령 권한을 찾아내고, 그 결과가 Day4의 '자동 회수봇' 입력이 됩니다.

## 오늘의 최종 목표 (Day 3을 마치면)
- [ ] 권한이 왜 시간이 지날수록 '과다'해지는지 설명한다(권한 누적·권한 크리프)
- [ ] 정기 점검의 자동 항목과 수동 항목을 구분한다
- [ ] `detect_unused_permissions()`로 90일 미사용 권한을 찾는다
- [ ] `detect_dept_mismatch()`로 부서와 안 맞는 권한을 찾는다
- [ ] 경계값(딱 90일째)에서 부등호(`>` vs `>=`)가 왜 중요한지 안다
- [ ] 탐지 결과를 종합 리포트로 묶고, 왜 '탐지≠즉시회수'인지 안다
