# 강의1 · 정책 로그 구조와 필드 해석 (오전, 총 120분)

> **이 교시 한 문장:** PDP/PEP가 접근을 판단·집행할 때마다 남기는 **정책 로그**를 필드 단위로 읽고, 여러 줄을 모아 **패턴(이상 징후)**을 찾습니다.

| 시간 | 소주제 | 핵심 한 줄 |
|------|--------|-----------|
| 00-25분 | 정책 로그란 | 접근의 '출입 기록부' |
| 25-55분 | 주요 필드 | 누가·무엇에·어떤 결정·왜 |
| 55-85분 | 패턴 분석 | 한 줄이 아니라 '모아서' 본다 |
| 85-110분 | 1과목 자동화 연결 | JSON 파싱·필터링 재사용 |
| 110-120분 | 정리 | 문서화로 |

## 이 교시에 나오는 어려운 용어
| 용어 (한글발음) | 한 줄 뜻 (아주 쉽게) | 비유 |
|----------------|----------------------|------|
| **정책 로그** | 누가·언제·무엇에 접근을 허용/거부했는지 기록 | 출입 기록부 |
| **필드(field)** | 로그 한 줄을 이루는 각 항목 | 표의 각 칸 |
| **action(allow/deny)** | 허용 / 거부 결정 | 통과 / 차단 도장 |
| **risk_score(리스크 스코어)** | 그 요청의 위험도 점수 | 위험 온도계 |
| **device_posture(디바이스 포스처)** | 기기 보안 상태(백신·패치 등) | 건강검진 결과 |
| **두괄식** | 결론을 맨 앞에 말하기 | 헤드라인 먼저 |
| **결론-근거-권고** | 무슨 일→데이터→할 일 3단 | 진단서 형식 |

## ⏱️ 00-25분 · 정책 로그란 무엇인가

!!! abstract "이 블록을 마치면"
    ✔ 정책 로그가 ==사후 감사·이상탐지의 핵심 데이터==인 이유를 설명한다

**정책 로그**는 PDP/PEP가 접근 요청을 판단·집행할 때마다 남기는 기록입니다. **누가 / 언제 / 무엇에 / 어떤 결정**이 났는지 한 줄씩 쌓입니다.

!!! example "쉬운 비유 — 출입 기록부"
    건물 출입구의 기록부처럼, 정책 로그는 "김철수가 09:15에 인사시스템에 접근 시도 → 거부됨(기기 기준 미달)"을 남깁니다. 이 기록이 있어야 ==나중에 "무슨 일이 있었나"를 되짚고(감사), 이상한 패턴을 찾을 수(탐지)== 있습니다.

!!! question "확인질문"
    **Q. 접근이 거부된 로그가 특정 사용자에게 반복적으로 쌓인다면 무엇을 의심해볼 수 있을까요?**

    **A.** ① 계정 탈취 시도(비밀번호 무차별 대입), ② 권한 설정 오류(정상 사용자가 못 들어감), ③ 감염 기기의 반복 접근을 의심합니다. **반복되는 deny**는 강한 신호입니다.

## ⏱️ 25-55분 · 정책 로그 주요 필드

!!! abstract "이 블록을 마치면"
    ✔ 로그 한 줄의 각 필드를 읽고 '무엇을 조치할지' 판단한다

### 🔬 깊이 보기 — 정책 로그 필드 완전정복

실제 로그 한 줄(JSON 형태) 예시:
```json
{
  "timestamp": "2026-07-07T09:15:00",
  "user": "kim01",
  "resource": "hr-system",
  "action": "deny",
  "reason": "device_posture_fail",
  "risk_score": 78
}
```

| 필드 | 뜻 | 이 예시에서 |
|------|-----|-------------|
| `timestamp` | 언제 | 2026-07-07 09:15 |
| `user` | 누가 | kim01 |
| `resource` | 무엇에 | 인사시스템 |
| `action` | 결정 | **deny(거부)** |
| `reason` | 왜 | **기기 상태 기준 미달** |
| `risk_score` | 위험도 | 78 (높음) |

**읽는 법:** "kim01이 인사시스템 접근을 시도했으나, **기기 보안 기준 미달**로 거부됐고 위험도가 78로 높다." → 조치: 그 사람의 **기기 백신·패치 상태를 먼저 점검**.

!!! question "확인질문"
    **Q. 이 로그에서 접근이 거부된 이유는 무엇이며, 담당자는 무엇을 먼저 조치해야 할까요?**

    **A.** 이유는 **`device_posture_fail`(기기 보안 상태 기준 미달)**입니다. 담당자는 kim01의 **기기 상태(백신·패치·회사 등록 여부)를 점검·보완**하도록 안내해야 합니다. 계정 문제가 아니라 기기 문제입니다.

<button class="quiz-opt">risk_score가 78이라 무조건 계정을 정지해야 하기 때문</button>
<button class="quiz-opt" data-correct>거부 사유(reason) 필드가 '기기 상태 미달'을 명시하므로, 신원이 아니라 기기 보안(백신·패치)이 원인이기 때문</button>
<button class="quiz-opt">action이 deny면 항상 비밀번호를 바꿔야 하기 때문</button>

## ⏱️ 55-85분 · 정책 로그 패턴 분석

!!! abstract "이 블록을 마치면"
    ✔ 한 줄이 아니라 ==여러 줄을 모아 드러나는 패턴==을 찾는다

로그는 **한 줄로는 별일 아니어도, 모아 보면 패턴**이 드러납니다.

- 특정 시간대에 **deny 급증** → 무차별 대입 시도?
- 한 리소스에 **같은 사용자가 반복 시도** → 권한 오류 또는 공격?
- **새벽 시간대**에만 특정 자원 접근 → 정상 업무인가, 침입인가?

!!! example "쉬운 비유 — 점 하나 vs 그래프"
    점 하나(로그 한 줄)로는 추세를 모릅니다. 점을 여러 개 찍어 **선(패턴)**으로 봐야 "새벽마다 몰린다" 같은 게 보입니다. 4과목(이상탐지)이 바로 이 '패턴 보기'를 자동화합니다.

!!! question "확인질문"
    **Q. 새벽 시간대에만 특정 리소스에 대한 deny 로그가 몰려 있다면 무엇을 의심할 수 있을까요?**

    **A.** 정상 근무 시간이 아닌 시각의 반복 거부이므로 **자동화된 공격(무차별 대입·스크립트)이나 감염 기기의 접근 시도**를 의심합니다. 사람이 새벽에 수십 번 실패하며 시도하는 건 드물기 때문입니다.

## ⏱️ 85-110분 · 정책 로그와 1과목 자동화 스킬의 연결

!!! abstract "이 블록을 마치면"
    ✔ 1과목의 JSON 파싱·필터링이 로그 분석에 그대로 쓰임을 확인한다

정책 로그는 대부분 **JSON**입니다. 1과목에서 배운 **JSON 파싱·필터링** 스킬이 그대로 적용됩니다.

- "action이 deny인 것만" → 필터링
- "risk_score ≥ 70인 것만" → 조건 필터
- "user별로 몇 번 거부됐나" → 집계

!!! tip "실무 팁"
    1과목에서 만든 **로그 필터링 함수**를 정책 로그에도 재사용할 수 있습니다. 데이터 형식(JSON)과 사고(필터→집계)가 같기 때문입니다. "한 번 만든 도구를 다른 데이터에 재사용"이 자동화의 핵심입니다.

!!! question "확인질문"
    **Q. 1과목에서 만든 로그 필터링 함수를 이 정책 로그에도 그대로 쓸 수 있을까요?**

    **A.** 네, 대부분 그대로 또는 약간 수정해 쓸 수 있습니다. 둘 다 **JSON 구조 + 필터/집계**라는 같은 형태이기 때문입니다. 필드 이름만 맞춰 주면 됩니다.

## ⏱️ 110-120분 · 정리 & 오후 예고

- **정책 로그**: 접근의 출입 기록부(감사·탐지의 근거)
- **필드**: timestamp·user·resource·action·reason·risk_score → `reason`이 원인을 콕 집음
- **패턴**: 한 줄이 아니라 모아서 → 시간대 집중·반복 시도 발견
- **재사용**: 1과목 JSON 파싱·필터링 그대로

**오후 예고:** 이렇게 읽은 로그를, **비전문가(고객)가 이해할 문서**로 바꾸는 법을 배웁니다.

## ✅ 가르칠 준비 체크리스트 (강의1)

- [ ] 정책 로그를 '출입 기록부'로 설명한다
- [ ] 로그 한 줄의 6개 필드를 읽고 조치를 판단한다
- [ ] 여러 줄을 모아 패턴(시간대·반복)을 찾는다
- [ ] 1과목 JSON 필터링 재사용을 설명한다
- [ ] 확인질문 4개 + 퀴즈에 답한다

*[JSON]: JavaScript Object Notation — 키·값으로 데이터를 표현하는 형식
*[PDP]: Policy Decision Point — 접근을 판단하는 정책 결정점
*[PEP]: Policy Enforcement Point — 결정을 집행하는 정책 집행점
