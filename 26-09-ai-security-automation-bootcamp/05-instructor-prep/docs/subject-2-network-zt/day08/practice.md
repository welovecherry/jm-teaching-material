# 실습 · 팀별 이슈 도식화 및 발표 (총 120분)

!!! note "자리표시 — 뼈대만 (강사가 직접 채웁니다)"
    실습은 강사가 먼저 도식화·발표를 준비해보고 함정을 기록하는 성격입니다. 상세교안의 진행 단계만 잡아 두었습니다.

> **실습 목표:** 장애·위협·접근통제 이슈 중 하나를 골라 도식화하고, 학습을 종합해 팀별로 발표한다.

## 진행 단계 (상세교안 기준)

1. 팀별로 장애/위협/접근통제 이슈 시나리오 하나 선택 (예: DNS 스푸핑 의심 사고)
2. 이슈 발생~대응까지 흐름을 **플로우차트 또는 타임라인**으로 도식화
3. 도식에 1~7일차 개념이 어디에 적용됐는지 라벨로 표시
4. `network_zt/day08_issue_diagram.png`로 저장
5. 5분 내외 발표 자료 준비 → 팀별 발표
6. 피드백·개선점을 `network_zt/day08_retrospective.md`에 정리(캡스톤 착수 참고)

**산출물:** `network_zt/day08_issue_diagram.png`, `network_zt/day08_retrospective.md`

## (작성 예정) 강사 예습 포인트

- 강사가 **먼저 한 시나리오를 도식화**해보고, 학생이 흐름을 논리적으로 못 잇는 지점 기록
- "이 단계 = 며칠차 개념" 라벨링 예시로 학습-실무 연결을 보여주기
- 발표에서 캡스톤 연결점을 어떻게 설명할지 대본 준비

## 평가 기준 (상세교안)

- 이슈 대응 흐름이 논리적으로 도식화되었는가
- 학습한 핵심 개념이 도식에 반영되었는가
- 발표에서 캡스톤과의 연결점을 설명할 수 있는가
