# 실습 · 기존 탐지룰 튜닝(오탐 감소) (총 120분)

!!! note "자리표시 — 뼈대만 (강사가 직접 채웁니다)"
    실습 베이스라인 코드·상세 문제는 강사가 직접 작성합니다. 상세교안의 진행 단계만 잡아 두었습니다.

> **실습 목표:** 라벨링된 테스트 데이터로 현재 탐지 성능을 측정하고, 오탐을 줄이는 방향으로 룰을 튜닝한다.

## 진행 단계 (상세교안 기준)

1. `anomaly_detection/evaluation.py`에 `evaluate_detector()`를 구현한다(0 나눗셈 방어 포함)
2. 제공된 라벨링 테스트셋(`is_actual_anomaly` 필드, 30건 내외)으로 2~3일차 탐지 함수들의 초기 정밀도·재현율을 측정한다
3. False Positive 사례 최소 3건을 직접 검토해 원인을 `anomaly_detection/day04_fp_analysis.md`에 기록한다
4. 원인에 따라 예외 조건 추가 또는 임계값 조정으로 룰을 1회 이상 개선한다
5. 튜닝 후 다시 `evaluate_detector()`로 성능을 측정해 튜닝 전후를 비교한다
6. 비교 결과를 표로 `anomaly_detection/day04_tuning_result.md`에 정리한다

**산출물:** `anomaly_detection/evaluation.py`, `day04_fp_analysis.md`, `day04_tuning_result.md`

## (작성 예정) 강사 예습 포인트

- 강사가 **먼저** 라벨링 테스트셋(정상/이상 섞고 `is_actual_anomaly` 부여)을 만들어 초기 정밀도·재현율을 측정
- **좋은 튜닝 vs 나쁜 튜닝** 둘 다 재현: 예외를 적당히 준 경우 vs 너무 넓게 준 경우의 재현율 차이(강의2와 연결)
- FP 사례에 '보안관제팀 계정' 같은 정당한 오탐 유발 케이스를 심어, 예외 처방을 유도
- 학생이 자주 막히는 지점 기록:
  - 정밀도만 보고 "개선됐다" 판단(재현율 확인 누락)
  - 0 나눗셈 방어 누락
  - 예외를 너무 넓게 줘 미탐 급증
  - 라벨(정답) 없이 성능 측정하려다 막힘

## 평가 기준 (상세교안)

- 정밀도·재현율이 올바르게 계산되는가
- 오탐 원인 분석이 구체적 근거를 갖는가
- 튜닝 전후 성능 비교가 명확히 제시되었는가
